# Opus 5.5 程式動畫 Prompt 範本

整理自 yihui-dev/awesome-opus5-5-videos（513 個 prompt）。
共通做法：請模型把動畫「寫成程式碼」（單一 HTML、Canvas、SVG、GSAP、Three.js），不是用影片生成模型。

## 通用原則
1. 先講**時長**與**格式**：「15 秒」「單一 HTML 頁面」「直式 45–50 秒」。
2. 給**角色**：「你是資深動態設計師」。
3. 給**品質標準與負面約束**：「不要通用 SaaS 模板」「不要憑空編造數字」。
4. 指定**真實素材來源**（網站網址、專案內的 design token、截圖），不要讓它亂編。
5. 要**分場景**時，明寫場景數與每場內容；短 prompt 加 "go all out" 也有效。
6. 配色、音樂也可以用程式處理（Web Audio、合成波形）。
7. 迭代少：1 個 prompt 加 1～2 輪回饋。

## 範本 A：品牌動態圖形短片（15 秒）
```text
你是資深動態設計師。為 <網站網址 / 產品名稱> 製作一支 15 秒動態圖形短片，
像用來求職的 showreel。輸出為單一 HTML 頁面。
- 先檢視 <品牌色 / logo / 截圖路徑>，只使用真實素材。
- 節奏快、場景之間自然轉場，有美術指導感而不是特效堆疊。
- 不要通用 SaaS 模板；不要編造數字或功能。
Go all out.
```

## 範本 B：30 秒產品解說（5 場景）
```text
扮演專業動態設計師。為我的事業製作 30 秒動畫解說，單一 HTML 頁面，共 5 場景：
1) 客戶的問題 2) 我做什麼 3) 三步驟如何運作 4) 一個佐證 5) 結尾署名。
粗體文字、平滑轉場、使用我的品牌色。
我的事業：<賣什麼、給誰、品牌色>
```

## 範本 C：概念教學動畫（3D）
```text
用 Three.js 製作 <概念，例如梯度下降> 的 3D 動畫：
- 視覺化：<例如球從山頂沿路徑滾到谷底>
- 旁白文字說明它是哪一類演算法與主要用途
- 轉場用淡入淡出；配色 <色一、色二、灰階漸層>
```

## 範本 D：可探索的 3D 世界
```text
建立可用相機自由探索的瀏覽器 3D 世界，重氛圍與構圖，非遊戲、無戰鬥。
地景：<峽谷、森林、水域>；建築：巨大、怪異、全新原創的結構。
要有史詩感與高細節。
```

## 範本 E：App 功能短片（直式）
```text
製作 45–50 秒直式影片介紹我的 app。
- 真實錄製：在模擬器中操作每個功能，畫面數字與標籤只能來自錄影。
- 每個功能至少停留 2.5 秒；文字避開 TikTok/IG 介面區域。
- 動態設計師 showreel 水準；不加音效，我自己配樂。
```

## 範本 F：導演腳本式（長 prompt 結構）
```text
SCENE CONTEXT：時間、地點、角色、事件順序、總時長與切點數
LOCATION MAP：每個場景的尺寸、材質、光源、畫面構成（寫具體數字）
CAMERA：機位與切換規則
STYLE：參考風格（例如 Apple 發表片 × 編輯式動態設計）
CONSTRAINTS：不要什麼、不能覆蓋什麼
```
